# 相册开发环境的媒体处理

> 历史方案：当前共享测试环境已迁移到 `platform_test_deploy.py` 管理的相册 worker。本文仅保留旧环境的配置恢复记录；请勿对新 worker 使用这里的激活步骤。当前方案见 `host-artifact-lifecycle.md`。

共享测试 API 与相册专用媒体 worker 分开运行。`readyz` 返回成功不代表图片或视频处理已开启；应核对实际 worker 的 `ALBUM_PHOTO_PROCESSING_ENABLED`、`ALBUM_VIDEO_PROCESSING_ENABLED` 和 CI 队列。2026-10-25 读取的 worker 仍为初始关闭配置，测试库账户、上传计数均为 0。

`deploy/tencent/albums_media.py` 只给现有开发 worker 叠加两个处理开关，保留原镜像、配置、数据库、凭据、网络和共享 API。它不配置分享、删除、订阅或生产环境，也不替代真实 Apple Sandbox 购买及媒体处理验收。

## 准备与激活

1. 在受控运维代码更新中安装经验证的 `albums_media.py` 与 `albums_artifacts.py`。二者必须与执行候选逐字节一致；仅把新版放在暂存目录不足以激活，避免这次操作能备份、后续定时备份却遗漏媒体配置。后续发布也必须保留这项恢复能力。
2. 以 `/opt/tellyouwhat/backend` 的所有者运行 `python3 deploy/tencent/albums_media.py --run <32位十六进制运行标识> --prepare`。它检查当前登记源、镜像、环境和资源隔离，保存开关关闭/开启的两份最小 Compose 配置，原状态原文，以及原文件和不应重启容器的摘要。准备不启动服务。
3. 核对候选后，使用同一脚本和 `--run`，省略 `--prepare`。默认入口通过现有 `development_deploy` 持有运维与部署锁，执行、登记产物并调用所属范围清理；不要直接传 `--activate` 或手工运行 Docker 命令。
4. 激活前重新核对全部输入，要求已有完整且已认证的相册数据库和配置备份。只运行 `albumworker` 的 `up --no-build --no-deps`，核对镜像 ID、环境唯一差异、无密钥挂载、网络及启动完成日志，并确认共享测试 API、其他测试服务和数据库的容器 ID 没变。
5. 成功后把媒体配置绑定写入既有相册状态，创建并验证新的恢复包。恢复包必须包含原配置、开启配置、原状态原文和摘要清单；任何启动或后置备份失败都会重新应用原 worker 配置，并在验证通过后恢复原状态。回滚配置不代表撤销已经提交给供应商的处理任务，任务和数据不清空。

激活前先持久化 `attempt.json` 和已验证的前置备份凭据。进程中断后，先确认没有遗留的同项目 Compose 操作，再用同一脚本、同一 `--run` 加 `--recover` 恢复；恢复也经过登记入口和双锁。若原状态、镜像或无关配置已经变化，拒绝自动覆盖，保留现场。已完成后置备份的操作可用原命令重试，它重新验证运行状态和备份，不重复启动 worker。普通异常自动回滚成功后保留记录；下一次启用使用新的准备目录。

运行目录位于 `.albums-development/media/<run>`，由此生产者创建，并与原源目录、实际镜像一起登记到 `albums-test`。它包含恢复所需配置，属于保留材料，不按临时缓存删除。中断或失败后先检查状态和实际 Compose 引用；不得仅按时间删除未决配置，也不得反复创建新运行掩盖原操作结果。

## 验证范围

本地测试覆盖过期输入、锁、镜像/挂载隔离、非法覆盖文件、启动失败回滚、后置备份失败回滚、未安装定时恢复支持时拒绝激活，中断发生在状态写入前后的恢复、成功操作重试、遗留 Compose 进程拦截、损坏日志拒绝，以及恢复包往返核验。测试使用合成配置与模拟容器命令，不能证明真实 COS/CI 请求或 Apple 订阅成功。

最终验收需分别记录：运维代码已安装、worker 开关与启动核验、真实照片/视频处理、实况配对、系统日常版回读、原件恢复和真实 Sandbox 权益。不能把进程运行或公开健康检查作为上述功能已完成的证据。
