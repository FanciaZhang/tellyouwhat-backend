# Offer 发放与核销管理

## 交付范围

Offer 管理覆盖 Apple 库存、领取申请、具名发放、领取反馈和核销证据。每一项统计都标明环境、来源和同步时间。

- Offer 清单：参考名称、订阅产品、启停状态、有效期、正式与沙盒额度。
- 码池清单：类型、生成额度、导入数量、确认可分配数量、外部状态待补录数量、已分配数量。
- 领取台账：姓名或昵称、联系方式或内部编号、渠道、备注、申请时间、处理状态、分配与发放时间。
- 人工发放：登记对象、分配码、再次验证后查看或复制码、记录实际发放，支持补录外部发放。
- 链接申请：限时领取入口、申请回执、后台审批、申请人查看自己的处理结果，明确区分申请与实际领取。
- 核销追踪：Apple 已验证的 Offer 核销订阅、领取人反馈、管理员关联的已验证订阅分别保留来源。
- 报表核对：Apple 官方核销报表按日期、Offer、环境和自定义码汇总；重复导入不重复计数，缺失日期不推断为零。

## 统计口径

App Store 交易中的 Offer 标识是参考名称，不能用 App Store Connect 的资源 ID 匹配。Offer Code 使用 offer type 3，推广优惠与其他优惠类型不混入统计。已验证核销订阅按原始订阅去重；同一优惠周期中的重复通知、恢复和后续交易不增加领取人数。

500 次生成额度不代表 500 次已发放，也不代表还有 500 次可用。统计读取失败显示不可用；未观测到交易不证明没有核销。正式环境与沙盒单独展示。Offer 已停用或写操作关闭时，仍可查看库存与历史记录。

Apple 的订阅优惠核销报表对一次性码不返回具体码值。领取人反馈不是 Apple 核销证据。管理员可将已验证的同 App、同环境、同 Offer 订阅关联到一条发放记录，界面明确标为人工关联；不能据此声称 Apple 验证了领取人的姓名或具体一次性码。同一已验证订阅不得关联给多名领取人。

参考：[Apple Offer 标识](https://developer.apple.com/documentation/storekit/transaction/offerid)、[Apple 核销报表字段](https://developer.apple.com/help/app-store-connect/reference/reporting/subscription-offer-redemption-report)。

## 数据与权限

姓名、联系方式、内部编号、备注及码值在数据库中加密。加密上下文绑定 App、记录类型和记录 ID。后台按已有 App 范围校验权限；敏感码查看要求再次验证，响应禁止缓存。普通审计只记录操作者、记录 ID、动作、数量和时间，不记录码值、联系方式或备注。

完整 CSV 导入默认视为外部状态待补录。运营确认未发放的码后才能加入可分配库存。导出会先将可分配码移出平台库存，避免平台内外重复发放。已分配码即使申请取消也不能自动回收。

申请记录采用幂等键，分配与状态变更采用数据库事务和版本校验。自定义码可以关联多个领取人，但平台分配数量受配置容量约束；平台分配上限不等同于 Apple 实际剩余核销次数。

## 验收要求

- 生成 500、已验证核销 3 的样例按参考名称正确展示；接口失败不变为 0。
- 一次性码、自定义码、正式与沙盒、过期及停用 Offer 都能查看。
- 申请、分配、发放、反馈与已验证关联分别统计，具名台账可检索与分页。
- 重复请求、并发分配、取消和 CSV 导出不会让同一码重复进入库存。
- 领取链接不泄露其他申请人的记录；过期、撤销、限额和重复请求均验证。
- Apple 报表、已验证交易与人工反馈不合并相加，不将不完整历史当作零使用。
- 手机宽度、键盘输入、中文输入、错误恢复、权限与跨 App 隔离均有验收。
- 发布前完成生成合约校验、数据库测试和 CI；部署后核对静态资源、迁移与真实库存统计。

## 申请入口与回执

申请链接最多开放三十天，配置独立的申请数量上限。每条申请都需要领取人同意保存申请信息；姓名或昵称为必填项，联系方式可选。渠道由链接配置确定，不能由申请人改写归因。申请数量与自然人人数不同；姓名与联系方式属于自行提供的信息，并非经过身份认证。

链接和查询回执使用独立用途的服务端签名，放在 URL fragment 中，通过请求体发送；服务端不存储明文链接或回执。查询回执有效期为九十天，只能访问对应申请的状态；管理员分配后，领取人主动查看码才记录为已发放。撤销申请链接仅停止新增申请，不撤销已有申请和已分配码。链接不触发邮件或消息发送，管理员自行复制并发送。

姓名和联系方式检索使用经过鉴权与 CSRF 校验的 POST 请求体，不放在 URL 查询参数中。公共领取接口不使用管理员 Cookie，单个来源每分钟最多三十次请求，并通过数据库锁保证申请上限和重复请求的一致性。服务的预览签名密钥变更会使旧领取链接及回执失效。

历史发放补录记录实际发放时间、领取人和已发出的具体码，不产生新的领取申请。一枚一次性码必须已经存在于已导入库存中，且不能已关联其他领取人。已过期或停用的码池仍允许补录历史，不开放新的分配。
