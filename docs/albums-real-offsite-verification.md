# 相册独立测试备份实测

2026-11-05，使用已获授权的两套编程身份，仅访问广州相册测试备份桶 `tellyouwhat-albums-backups-test-1251995834` 的 `albums/recovery/*`。`albums-test-backup` 负责发布与读取，`albums-test-backup-expiry` 负责核验和精确版本清理；两份云凭据仅保存本机 0600 配置，没有复制到服务器。

## 通过范围

- 真实 COS 分片上传合成加密快照与回执，按明确版本取回并核对摘要。
- 本机无网络 MySQL 恢复 42 张表，核对行数与内容，应用删除清单并隔离会话、分享等访问入口。
- 仅清理本轮合成对象对。最终回执为 `Empty=true`、`UploadsEmpty=true`、`VersionsRemoved=2`、`SessionsClosed=2`。
- 联合集成用例 1 项通过、0 失败、0 跳过；探针边界用例 7 项通过、0 失败、0 跳过。

## 失败与修复

首次真实上传、取回和清理通过，但恢复数据库启动失败。相同 MySQL 8.4 在 145 字节 socket 路径返回 `The socket file path is too long (> 103)`，46 字节路径正常启动；数据库内容和 COS 权限并非本次失败原因。

仅修改 `offsite_probe.run` 的恢复临时根目录，复用调用方已验证的 `/tmp/album-snapshot-*` 夹具；实际恢复文件及加密密钥仍来自本轮持久探针目录。普通备份/恢复实现、源数据库限制、socket-only 命令核验及云权限范围保持原状。新回归在原实现失败，修复后通过；中途修正了测试中的 `/var` 与 `/private/var` 路径别名断言。

第二次使用全新探针目录与新合成快照，保留第一次失败报告，未重复发布未知结果。两次云清理均已确认；联合用例退出后，经签名、摘要和锁核对，只移除这两次探针自己生成的本地快照、副本与临时加密密钥，保留报告、签名回执、源码快照和诊断。云凭据与历史备份未删除。
