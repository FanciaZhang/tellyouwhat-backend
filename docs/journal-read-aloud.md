# Journal 全文朗读服务

2026-10-20，实施中。产品与 App 验收基线在 JournalApp 仓库的 `docs/read-aloud-product-plan.md`。本文记录后端实际进度，不代表 TTS 已开通、已部署或 App 已完成联调。

## 已有基础

- `internal/journal/readaloud/provider.go`：豆包语音合成 2.0 HTTP 单向流，固定公共音色资源、24 kHz 单声道 PCM、单请求文本和音频边界。检查终止帧，取消和消费者失败不自动重试，重定向不转发密钥，错误不携带供应商原始响应正文。
- `catalog.go`：公共目录只输出展示及能力信息；启用音色需要标准计费类别和能力探测证据。新增能力使旧证据失效，空目录、重复 ID 或无效默认声音不能发布。当前仅有领域校验和探测逻辑，尚无持久目录、后台页面或官方目录同步。
- `metered.go`：合成前接入既有项目费用预留，按 Unicode 字符计量；客户端取消仍执行结算。用量不明确时保留预留，费用准入失败不调用供应商。测试默认标准价格为每字符 300,000 CNY nanos，即 3 元／万字符；上线由服务端核对实际计费配置。
- `quota.go` 与迁移 `0068`：持久字符额度及请求指纹。只有首次原子申请取得一次合成资格，重放返回既有状态；不同文字、声音、能力参数或来源版本不能复用请求 ID。正文朗读和固定短句试听拥有独立额度账户，可配置不同周期；额度及周期必须来自可信服务端权益。表内没有正文或私人音频。
- 供应商结果状态和费用确定性分开：音频完整成功但没有实际字符回执时仍可标记成功，同时保留字符预留；后续权威用量只能结算一次。结果未知的请求不会因为进程重建而重新获得合成资格。

## 当前验证

`go test -race ./internal/journal/readaloud ./migrations` 通过。朗读包本机有 15 项逻辑及协议测试通过，另两项 MySQL 检查按本机无 DSN 明确跳过；本机的跳过结果不作为数据库通过依据。

两项 MySQL 检查已另外编译成同源码 Linux 测试程序，在现有 `tellyouwhat-platform-test-mysql-1` 上用临时受限测试账号运行，均通过：

1. 12 个并发请求仅有一个首次申请；运行中不能重复申请；未知费用在存储对象重建后保留；权威结算只发生一次；额度不足拒绝新请求；迁移重放保留既有账本；音频成功但用量未知时保持成功状态及费用预留。
2. 请求不能跨主体读取或改成另一段文字；试听和正文额度独立；确定未调用供应商的零费用取消释放预留。

每次检查使用新的隔离数据库，测试结束已核对专用初始数据库、临时账号和测试程序均删除，没有遗留新增测试数据库。未迁移现有业务数据库，未切换网关或 worker，未调用真实豆包服务。
