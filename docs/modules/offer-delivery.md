# Offer 发放与核销管理

## 交付范围

Offer 管理覆盖 Apple 库存、领取申请、具名发放、领取反馈和核销证据。每一项统计都标明环境、来源和同步时间。

- Offer 清单：参考名称、订阅产品、启停状态、有效期、正式与沙盒额度。
- 码池清单：类型、生成额度、导入数量、确认可分配数量、外部状态待补录数量、已分配数量。
- 领取台账：姓名或昵称、联系方式或内部编号、渠道、备注、申请时间、处理状态、分配与发放时间。
- 人工发放：登记对象、分配码、再次验证后查看或复制码、记录实际发放，支持补录外部发放。
- 专属领取链接：管理员给已分配的记录生成链接，领取人直接查看兑换码，无需填写姓名、邮箱或登录 Apple。链接可撤销和重新签发。
- 核销追踪：Apple 已验证的 Offer 核销订阅、领取人反馈、管理员关联的已验证订阅分别保留来源。
- 报表核对：通过 Apple API 定期读取正式环境的官方日报，按日期、订阅产品、Offer 和自定义码汇总；重复同步不重复计数，缺失日期不推断为零。

## 统计口径

App Store 交易中的 Offer 标识是参考名称，不能用 App Store Connect 的资源 ID 匹配。Offer Code 使用 offer type 3，推广优惠与其他优惠类型不混入统计。已验证核销订阅按原始订阅去重；同一优惠周期中的重复通知、恢复和后续交易不增加领取人数。

500 次生成额度不代表 500 次已发放，也不代表还有 500 次可用。统计读取失败显示不可用；未观测到交易不证明没有核销。正式环境与沙盒单独展示。Offer 已停用或写操作关闭时，仍可查看库存与历史记录。

配置 App Apple ID 时，清单遍历此 App 的全部订阅组、订阅产品和 Offer，各层分页必须完整成功。只配置订阅资源 ID 时，页面明确标明清单范围。新建 Offer 使用配置的默认订阅产品，启用数量上限按该产品单独计算。

新的已验证核销记录保存同一笔 Apple 交易的产品 ID，按产品、参考名称和环境分别统计。同参考名称的历史记录缺少产品 ID 时保留在汇总中，单独展示为产品待确认，不推断归属，也不能关联到一个有明确产品的领取记录。首页的登记申请和发放统计来自已纳入台账的码池，未管理码池不推断为零。

Apple 的订阅优惠核销报表对一次性码不返回具体码值。领取人反馈不是 Apple 核销证据。管理员可将已验证的同 App、同环境、同 Offer 订阅关联到一条发放记录，界面明确标为人工关联；不能据此声称 Apple 验证了领取人的姓名或具体一次性码。同一已验证订阅不得关联给多名领取人。

参考：[Apple Offer 标识](https://developer.apple.com/documentation/storekit/transaction/offerid)、[Apple 核销报表字段](https://developer.apple.com/help/app-store-connect/reference/reporting/subscription-offer-redemption-report)。

## 数据与权限

姓名、联系方式、内部编号、备注及码值在数据库中加密。加密上下文绑定 App、记录类型和记录 ID。后台按已有 App 范围校验权限；敏感码查看要求再次验证，响应禁止缓存。普通审计只记录操作者、记录 ID、动作、数量和时间，不记录码值、联系方式或备注。

完整 CSV 导入默认视为外部状态待补录。运营确认未发放的码后才能加入可分配库存。导出会先将可分配码移出平台库存，避免平台内外重复发放。已分配码即使申请取消也不能自动回收。

申请记录采用幂等键，分配与状态变更采用数据库事务和版本校验。自定义码可以关联多个领取人，但平台分配数量受配置容量约束；平台分配上限不等同于 Apple 实际剩余核销次数。

## 验收要求

- 生成 500、已验证核销 3 的样例按参考名称正确展示；接口失败不变为 0。
- 一次性码、自定义码、正式与沙盒、过期及停用 Offer 都能查看。
- 申请、分配、发放、反馈与已验证关联分别统计，具名台账可检索与分页。
- 重复请求、并发分配、取消和 CSV 导出不会让同一码重复进入库存。
- 领取链接不收集个人资料，不泄露其他记录；过期、撤销、重新签发和重复请求均验证。
- Apple 报表、已验证交易与人工反馈不合并相加，不将不完整历史当作零使用。
- 手机宽度、键盘输入、中文输入、错误恢复、权限与跨 App 隔离均有验收。
- 发布前完成生成合约校验、数据库测试和 CI；部署后核对静态资源、迁移与真实库存统计。

## 专属领取链接

姓名或称呼由管理员在后台备注，领取人无需填写姓名、邮箱或其他个人信息，也不需要通过 Apple 登录。专属领取链接只指向一条已经分配兑换码的记录，不自动创建新的申请。打开链接查看状态不算发放，主动领取兑换码才记录为已发放。领取记录只能证明该链接被使用，不能证明领取者的 Apple 身份；转发链接会转移领取能力。

领取链接有效期为九十天，可在后台撤销或重新签发。服务端签名绑定 App、记录和撤销代数，重新签发不会恢复旧链接。密钥放在 URL fragment 中，通过请求体发送，服务端不保存明文链接。公共领取接口不使用管理员 Cookie；个人资料不发送到公共页面。令牌校验、撤销、码值读取和发放状态更新通过同一数据库事务串行化。

姓名和联系方式检索使用经过鉴权与 CSRF 校验的 POST 请求体，不放在 URL 查询参数中。公共领取接口单个来源每分钟最多三十次请求。服务的预览签名密钥变更会使旧领取链接失效。

历史发放补录记录实际发放时间、领取人和已发出的具体码，不产生新的领取申请。一枚一次性码必须已经存在于已导入库存中，且不能已关联其他领取人。已过期或停用的码池仍允许补录历史，不开放新的分配。

## Apple 核销日报

配置 `HEALTH_APP_STORE_CONNECT_VENDOR_NUMBER`、`JOURNAL_APP_STORE_CONNECT_VENDOR_NUMBER` 后，后台使用已有 App Store Connect 服务密钥，每六小时读取核销日报，并补齐最近 185 天可获取的历史。最近十四天重新读取以覆盖 Apple 的报表修正。需要具备销售与趋势报表权限；供应商编号不是 Apple ID，也不用于领取人登录。

API 请求使用 `SUBSCRIPTION_OFFER_CODE_REDEMPTION`、`SUMMARY`、`DAILY`、`1_0`。只有成功下载并完整解析的日报才能写入统计；404、鉴权失败、网络错误、损坏的压缩文件或字段异常不能形成零核销记录。每个 App、日期的报表原子替换，重复读取不累加，修正中删除的行也同步移除。数据库只保存当前 App 的汇总数据，具体自定义码以哈希匹配，不保存原始报表或其他 App 的数据。

自定义码可按具体码值查询 Apple 确认的兑换次数；相同码值的多个批次合并统计。一次性码字段为空，只能统计同订阅产品、同 Offer 的一次性码总量。页面显示实际取得的日期范围、天数、更新时间和同步失败状态，不将范围内缺失日期推断为零。Apple 报表统计与后端已验证订阅统计不合并相加。

熟人发放使用每人独立的自定义码，姓名或称呼只由管理员记录。专属链接的领取状态与 Apple 报表的兑换状态分开显示；码被转发后，只能确认该码兑换过，不能确认兑换者的 Apple 身份。线上批量发放继续使用一次性码或共享自定义码的汇总统计。

## 熟人专属发放

Offer 卡片提供“熟人发放”入口。管理员填写称呼和兑换截止日，后台生成随机自定义码并向 Apple 请求一次兑换额度，随后生成无需填写个人信息的领取链接。正式写入要求再次验证通行密钥。创建前先加密保存意图；网络中断后以原随机码核对 Apple，不能再次创建或自动提高兑换额度。Apple 明确拒绝时显示拒绝状态，不宣称创建成功。

发放记录分别保存人工发放时间、领取链接实际取码时间和 Apple 日报兑换结果。打开链接仅查看状态不会计为领取；领取成功后提供 Apple 官方兑换链接。历史人工发放不补造实际领取时间。主动给熟人准备的专属码单独标注来源，不冒充领取人的申请。重复创建请求不会恢复已撤销的领取链接。

兑换码到期按 Apple 的美国太平洋时间午夜计算，包含夏令时；领取链接自身有效期不延长兑换码有效期。
