# Journal development illustration delivery

The private `journaldevserver` now accepts the App's confirmed illustration task contract, independently of the shared production gateway. It supports authenticated create, status, result and cancellation routes and the separate `journal_illustration` consent dated 2026-09-27. Text consent alone does not authorize image upload. Image approval and withdrawal persist encrypted across service restart. Cancellation remains available to the authenticated owner after image consent or entitlement withdrawal.

Explicit runtime configuration: `JOURNAL_IMAGE_ENABLED=true`, `JOURNAL_IMAGE_BASE_URL`, `JOURNAL_IMAGE_API_KEY`, `JOURNAL_IMAGE_MODEL_ID`, and a reviewed positive `JOURNAL_IMAGE_MAX_COST_NANOS` no greater than CNY 1. Images use the existing persistent developer monthly monetary ceiling and concurrency accounting. The current launcher ceiling is CNY 200. Provider keys remain on the server. No production database or Health service is opened.

The private state mount holds encrypted temporary image tasks and results with 24-hour delivery expiry. A server-local payload key is independent of the revocable connection credential. Authentication derives installation ownership from that credential; rotating it revokes old identities without preventing old payload expiry. Durable request digests bind approved text, reference bytes, version and consent. Replaying the same ID preserves the original task; changed material is rejected. A persisted running fence precedes the single provider call. HTTP disconnects do not discard accepted tasks, queued tasks recover, and interrupted running tasks become uncertain and are never dispatched again. Cancellation/expiry erases private input and output while retaining task tombstones. The scheduler caches task metadata to avoid decoding completed images every second.

The image adapter requests one 2K image with base64 output and watermark; it bounds network response size, image dimensions and bytes, disables redirects and never retries an uncertain provider call. Every attempt retains the conservative monetary reservation once dispatched; provider billing is authoritative. Real invoice reconciliation for uncertain upstream outcomes remains outside this developer runtime.

Task status includes an optional `problem` (`network`, `unavailable`, `quota`, `rejected`, or `invalidImage`). Explicit provider 401/403/404 failures terminate delivery as `rejected` with `unavailable`, rather than leaving an impossible delivery pending; billing uncertainty remains separate. The App persists this specific problem and never resubmits automatically. A model in the provider catalog does not establish account access. Live acceptance on 2026-10-05 remains blocked: the configured Seedream 4.5 model returns model-not-found/access-denied, and the current Seedream 4.0 replacement returns access-denied. Account activation and a successful synthetic image check are still required.

Focused verification: `go test -race ./internal/journal/illustration ./internal/journal/development ./cmd/journaldevserver ./internal/privacy ./internal/platformhttpapi ./internal/journalhttpapi ./internal/healthhttpapi`, plus `go vet` for the changed runtime/provider/command. Tests cover image consent, restart recovery, replay and material conflicts, encrypted storage, owner separation, cancellation races, result delivery, expiry, cost reservation and malformed upstream results. Fixtures do not prove live provider availability; live synthetic acceptance must be recorded separately.

Provider references: https://docs.volcengine.com/docs/ark/image-generation-api?lang=zh and https://docs.volcengine.com/docs/ark/model-pricing?lang=zh . Deployment configuration selects an explicitly available model and conservative cost bound; source defaults never enable spending.
