# 方舟管理服务

管理服务通过独立 IAM 服务身份调用国内方舟管控 API，使用固定区域 `cn-beijing`
及 API 版本 `2024-01-01`。推理请求继续使用单独的 Ark API Key。

`internal/arkcontrol` 仅从明确指定的本地 JSON 文件读取 `accessKey` 和
`secretKey`，文件权限为 `0400` 或 `0600`，大小不超过 8 KiB。文件缺失、权限
过宽或格式错误时拒绝启动该客户端，不读取环境变量或个人 CLI 登录配置。
凭证文件仅挂载给管理服务，不放入所有容器共享的环境文件或 secrets 目录。

已实现的管控操作为 `GetEndpoint`、`ListFoundationModels` 和
`ListFoundationModelVersions`。分页读取不返回不完整目录；上游错误和未声明
字段不会直接暴露给调用方。管理调用固定超时，不自动重试。

`SupportRolling` 未返回时表示未知，不能视为不支持。模型目录中的已发布状态
不证明账号可调用，也不证明某接入点可以升级到该模型。

灰度写操作需要验证国内方舟 API 的参数及状态转换后才能开放。不能使用模拟
响应代替云端验证，也不能使用生产接入点进行接口探测性写操作。

## 健康功能配置

管理后台提供健康功能配置、草稿、发布、历史版本载入及模型目录读取。
历史版本载入后生成新草稿，再发布为新版本。发布通过基线版本比较防止覆盖
其他管理员的修改；重复发布同一当前版本不会重复修改生效指针。

`0005_health_ai_config.sql` 必须先于新网关部署执行。配置及版本历史纳入现有
加密控制面备份。没有发布记录的功能维持原参数；已发布功能在同步、流式及
入队时读取配置。后台任务将快照写入现有加密载荷，Worker 不读取当前配置。
数据库配置读取失败时返回服务不可用，不静默退回客户端参数。

管理服务只允许配置已有健康绑定且仍运行已核验基线模型的 Endpoint；与手记
环境配置共享的 Endpoint 被排除。当前基线为 `doubao-seed-2-0-mini-260428`，
新增模型需要完成能力和费用验证。思考选项为关闭、轻度、中度和深度；联网
仅适用于 `meal_decision`。请求超时沿用服务端 `HEALTH_ARK_TIMEOUT_SECONDS`。

启用管理连接时，追加 `compose.ark-management.yaml`，在部署环境指定
`ARK_MANAGEMENT_CREDENTIAL_HOST_FILE` 的绝对路径。凭证文件不存在时 Compose
拒绝自动创建目录。默认部署不挂载管理凭证，AI 页面提示服务身份未配置。
管理写操作沿用现有写入控制及通行密钥再次验证。不要在部署配置或文档中写入
真实 AK/SK。

## 验收状态

原生模型升级、灰度写操作、自动状态核对及其费用切换尚未开放。后台明确显示
此状态，不提供不可执行的灰度按钮。模型目录不等同于可升级目标列表。

本地单元测试覆盖签名、凭证隔离、目录分页、配置快照、同步及流式策略应用。
`TestMySQLPublishCompareAndSwap` 需要 `MYSQL_TEST_DSN` 指向以 `_test` 结尾的
独立数据库，验证发布、重复提交和过期草稿冲突。缺少该配置时测试跳过，不能
作为数据库验收成功证据。完整浏览器操作、生产服务身份和测试 Endpoint 灰度
生命周期仍需独立验收。
