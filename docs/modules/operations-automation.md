# 自动巡检与故障保护

## 交付范围

- 管理服务每分钟巡检，不依赖浏览器打开；巡检心跳、采样时间和失联状态在后台展示。
- 高错误率、慢调用、预算接近上限、队列积压和超时未结算分别形成持久异常记录。重复巡检更新同一事件，恢复后保留过程。
- 高错误率支持自动保护：连续两个完整采样窗口达到阈值后，暂停该功能新的供应商调用；冷却后只放行一个真实请求试探，连续成功后恢复，失败则延长冷却。
- 模式、采样窗口、错误率、样本下限、冷却、恢复条件和积压阈值可以在管理后台配置，沿用草稿、差异预览、通行密钥发布和版本恢复。
- 运行页面集中呈现待处理异常、正在保护的功能、下一次试探时间及自动处置历史。人工暂停优先，自动恢复不会解除人工暂停。
- 服务器独立定时检查服务、磁盘和备份/维护/恢复演练的新鲜度；管理页面可识别过期的服务器巡检结果。

## 判断口径

自动保护只使用新版本记录的调用终态。用户取消不计供应商故障；旧数据、未知终态和缺失样本不当作成功。采样使用完整、互不重叠的 UTC 窗口；多实例、重启和重复巡检不会累计同一窗口。

默认保护条件为连续两个五分钟窗口、每个窗口至少二十次完成调用且错误率达到百分之六十。提醒使用单独的告警阈值。慢调用、预算接近上限和队列积压只产生事件，不自动切换模型或增加额度。

自动保护与人工配置分别保存。保护不会删除任务、扣除额外配额或重复提交已经发出的模型请求；排队任务保留原有效期。冷却后的试探使用正常鉴权、额度和预算检查，不发送合成计费请求。试探许可和费用预留在同一事务中提交，多个进程最多同时放行一个试探；请求失联按许可到期处理，不能永久占住恢复通道。

后台提供“仅记录异常”和“自动保护”模式。切换为仅记录会解除自动拦截，人工暂停和预算控制保持各自语义。模式变更和自动状态变化有独立记录。

## 数据与验收

事件只保存 App、功能、规则、聚合值、时间和动作，不保存用户标识、正文、Prompt、密钥或交易标识。告警以管理后台事件中心为通知入口；外部消息渠道需单独配置接收目的地。

验收包含真实 MySQL 的多实例竞争、重启恢复、重复窗口、试探独占、超时与迟到结果，正常鉴权/预算/队列路径回归，规则发布与手机端交互，以及生产环境只读心跳、规则、版本和服务就绪核验。不得在生产注入失败调用或修改用户预算来制造验收结果。
