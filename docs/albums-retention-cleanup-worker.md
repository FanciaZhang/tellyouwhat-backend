# 相册到期清理调度

2026-11-03：已接入现有相册 Gateway 的后台生命周期，源码已验证，尚未部署或启用。它不是新的公共 API 或独立服务。

## 行为

- 按六个自然月筛选到期账户，包含只有自建相册、没有媒体用量的账户。SQL 月末与闰年边界和领域规则一致，截止前一微秒不选中。
- 新清理先通过现有 Apple 全购买链核验，再在账户锁内消费短时证明。续费阻止尚未开始的删除；已经获得首次删除许可的媒体按持久计划继续核对，不能重新当作可用备份。
- 原件、派生及历史版本沿用现有逐项清理流程。只有重新列举确认对象为空，才提交媒体删除凭证、元数据移除和容量退还。分组名称和成员关系清空后保留删除标记。
- 账户级租约和游标持久保存；失败延迟重试，异常退出后可接管，旧回执不能覆盖新租约。无法清理的资产保留，下一个分页继续处理其他资产。空对象键的已核对进度不会因更换核验凭证而清零。
- 接入 `runGatewayBatch`，待机实例不领任务；暂停、排空和退出取消执行并保留恢复记录。账户注销标记生效后，单项清理向账户清理流程交接，旧证明不能继续清理分组。
- 日志仅记录批次计数和可用状态，不记录照片、相册名称、对象授权地址或账户凭据。

迁移 `0082_album_retention_cleanup_schedule.sql` 仅新增可空的调度字段及租约约束，不修改媒体、余额或既有授权。DDL 成功但未记账时可重放，已有调度状态保持。字段随相册完整加密备份恢复，恢复库继续隔离。

## 配置与尚未完成的验收

`ALBUM_RETENTION_ERASURE_ENABLED` 默认关闭。仅正式部署且已启用订阅校验时可配置为 `true`；正式服务的 Sandbox 子实例不继承它，开发部署拒绝启用。真实 Sandbox 到期不授权自动清理。

启用前仍须验证真实 COS 写入已收敛、删除凭证与最新检查点可恢复、历史备份的删除传播，以及真实账户流程。本轮没有请求真实 Apple/COS、删除用户媒体、开通新权限、部署或发布 App。

未关闭的上传或转码保持未决。本记录对应 `36f9a87` 的首轮验证；后续已补齐独立回收站计划的自动执行和最终截止优先规则，见[回收站调度](albums-trash-cleanup-worker.md)，仍未启用。历史备份与删除日志的最终擦除、完整账户注销也仍是完整产品目标的未完成项，不能把本轮调度实现当作全部数据已擦除。
