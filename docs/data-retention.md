# 数据保留与恢复边界

AI 任务和临时媒体具有最长 24 小时的服务有效期。任务 API 在准确到期时拒绝读取、取消和幂等重放旧结果，Worker 不再领取过期任务；数据库物理删除由每日 maintenance 执行。物理清理发生在下一次成功的清理作业，不承诺在服务到期瞬间完成。

任务物理清理覆盖排队、运行、成功、失败和取消状态，派发记录通过外键级联删除。对象存储删除失败时保留媒体元数据供重试；数据库清理不依赖对象存储清理成功。清理作业任一部分失败时整体状态为失败，不更新成功记录。

应用层备份不包含 `ai_jobs` 和 `job_dispatch_outbox` 的数据。备份最长保留 14 天，以 HMAC 验证后的创建时间判断期限，不使用可因复制而变化的文件时间戳。生成新备份前和每日 maintenance 均独立清理到期备份，因此新数据库导出失败不会延长旧备份的保留期。到期备份禁止进入恢复演练。

无法通过完整性校验的备份保留供运维核查，同时继续清理其他已验证的到期备份，并将作业标记为失败。运维须处理校验失败和清理失败告警，不能据此宣称全部副本已经删除。

云数据库快照独立于应用层备份，其保留周期和删除结果必须在云控制台或 API 单独核验。旧备份恢复可能带回已删除身份和已撤回同意；隔离恢复演练只证明备份完整性，不能授权恢复对外服务。生产恢复前必须完成到期数据清理、删除与撤回记录核对，并保留验收证据。当前删除完成摘要仅用于重试结果确认，不能用于识别备份中的全部待删除主体。
