# 统一测试管理后台

测试后台与正式后台采用同一套管理服务、页面和按 App 授权的架构。测试入口为 `https://admin-test.tellyouwhat.cn`，正式入口仍为 `https://admin.tellyouwhat.cn`。

## 范围与隔离

- 测试管理服务注册 Health、Journal、Birthday、Albums 四个 App，管理员可见全部 App；运营人员只可见分配给自己的 App。
- 运营、AI 管理、服务管理、通行密钥、人员、审计沿用现有后台。音色是 Journal 的子模块，不决定后台入口或其他 App 的注册范围。新增业务模块仍按实际产品需求实现。
- 页面在登录前后明确标识测试环境；App API 保留各自原有测试域名。Journal API 域名不再承载管理页面。
- 管理服务仅连接 `platform_test` 数据库、Redis DB 1 和测试网络，绑定 loopback 18792，非 root、只读根文件系统。测试写入作用于测试库。
- 四个 App 的 App Store Connect 客户端均明确禁用，不复制生产 Apple 凭据。未配置服务返回明确不可用状态；提示词、写作风格、音色等已存在模块保持独立。模型控制台需要独立的火山管理服务身份，当前未配置。
- WebAuthn RP 和 Origin 精确绑定测试后台域名。原 Journal 域名凭证不能跨域使用；使用既有账号恢复邀请，由用户自行登记新通行密钥。正式账号和生产通行密钥不迁移。

## 部署与恢复

走 `platform_test_deploy.py` 注册生产者更新，保留当前、可回退和运行中的候选，管理私有配置原样保留。已知上一版 Journal 专用配方只供匹配的回退及备份恢复读取，正常更新不允许缩小 App 范围。使用 `test_routes.py --enable health journal birthday albums --admin` 发布独立测试管理路由，保持正式 Caddy 主配置和生产部署状态摘要不变。

编译阶段的缓存带本次源码标记，构建结束后仅回收该源码未引用的无标签编译层；最终运行镜像从 scratch 开始，不继承编译标记。既有运行和回退镜像、业务数据、卷、私有配置和证据不在此清理范围。

本地验证包括四 App 配置、环境标识、匿名拒绝、运营跨 App 权限、未配置服务、匹配回退、完整恢复、路由失败恢复、编译缓存范围及移动/桌面页面几何检查。真实部署还必须核对来源/隔离/HTTPS/四 App 就绪/路由/清理，并通过带配置清单的认证备份与三个 COS 对象回读。
