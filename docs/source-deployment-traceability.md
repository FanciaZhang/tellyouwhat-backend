## 部署前条件

1. 对统一候选的准确提交完成真实 MySQL/Redis 测试、合同生成检查、Swift 合同测试、运维及隔离恢复测试，以及六个服务镜像构建。旧主分支上的独立 PR 验证不能代替本候选验证。
2. 核对 GitHub `production` 环境的配置与当前服务器配置，尤其是手记语音开关、供应商凭据、模型、订阅商品、代理模式和镜像来源。只记录字段是否匹配，不把凭据值写入源码、日志或构建产物。
3. 记录候选完整提交与镜像摘要。按发布授权激活这一候选；保留当前健康版本及配置快照作为回滚来源。数据库迁移必须兼容已有语音版本。
4. 验证内部就绪、公网 TLS、真实 App 的鉴权/权益，以及健康和手记的业务回归。更新生产对应关系后，才能将候选标为已部署。

发布工作流会用 GitHub 保存的配置替换服务器配置；完成一致性核对前，不能直接以旧主分支运行部署。
备份保留、云服务商快照、撤回或删除后的恢复处理仍需独立核对，不能用任务接口到期校验替代物理删除证明。
