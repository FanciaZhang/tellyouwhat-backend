# 共享恢复使用独立删除检查点

共享恢复演练可以为 development、production 分别指定一份独立取得的相册删除检查点。旧备份包仍须通过原有认证、摘要、保留期及数据库范围检查；额外文件在解密 SQL 或启动恢复数据库前核对固定 SHA-256、独立密钥签名、v3 范围、数据库与导出时间。任一失败即停止，不回退到包内旧记录继续恢复。

两份已认证记录合并重放：账户、资源及相册的旧删除记录继续保留；相同记录去重，资产版本列表按集合比较。同一项的凭证、修订、时间或资源集合冲突时拒绝，合并后继续检查记录总量和版本唯一性。不会把文件时间或单纯“较新”当作完整性证明。

## 使用

沿用原有登记运维入口。下面仅展示恢复命令的参数；文件和摘要应从经过认证的独立渠道取得，且匹配恢复包实际包含的环境：

```sh
python3 deploy/tencent/operations.py restore \
  --backend-dir /opt/tellyouwhat/backend \
  --backup mysql-YYYYMMDDTHHMMSSZ-abcdef.sql.gz.enc \
  --albums-checkpoint development /secure/dev-checkpoint.json SHA256 \
  --albums-checkpoint production /secure/prod-checkpoint.json SHA256
```

每个环境最多指定一次。没有选择项时沿用包内检查点；选择缺少恢复包的环境、错误摘要或未配对参数会报错。参数不能用于备份、维护或其他操作。COS 取回与本地恢复将同一选择传到最终 SQL 恢复器。

独立检查点存放在 COS 时，可用 `deploy/albums/backup.py fetch` 按认证回执取得固定版本，并使用返回的 `deletion_ledger` 路径和 `deletion_ledger_sha256` 作为选择参数。

源库仍可读时，可加 `--verify-albums-checkpoint-source`。指定的每个环境用自己的只读备份账户，在启动相册隔离库前和完成相册 SQL 重放后，将独立检查点与源库的账户、媒体和相册删除记录比较。共享库重放和行数核对结束后，恢复器再次按固定摘要认证独立文件，并在写共享成功回执前核对每个选定源库。源库不可用或任一次核对失败时，此模式返回失败，临时恢复库按原流程回收，已有成功回执保留。源库不可用时可运行原有隔离演练，回执只记录实际执行的检查。

共享成功回执附上各环境的独立检查点摘要及最后一次核对时间，单独的相册回执记录相册库重放前后的时间。每次比较只覆盖各自读到的数据库快照。线上恢复切换仍须另外排空在途写入并验证最新状态。

原检查点文件由提供方保管，恢复器只读取，不复制到备份包或删除。重放直接使用已认证的内存记录，并继续合并旧包中已认证的历史记录。最后一次核对重新认证文件及固定摘要。恢复工作区和临时数据库继续由已有租约与清理入口负责正常、失败、取消及异常退出处理。

## 验证与状态

2026-11-05：161 项定向测试通过、无跳过，覆盖两环境、命令参数、本地与云端调用链、三类记录合并、冲突、错误签名/摘要/范围、旧或未来时间、链接及权限检查，以及失败与清理保护。另在 socket-only MySQL 8.4 完成一项实际 SQL 集成：旧包内检查点与较新独立检查点共同恢复，三项资产删除、一项相册删除和一项账户删除重放成功，源数据和输入文件保留，恢复库保持隔离。Docker 运输由同一合成夹具适配到本机 MySQL，此次没有调用真实 Docker 或 COS。

第一轮两个夹具问题已保留：无效示例文件名被原工作区规则拒绝，以及错误地将清理器的只读 Docker 查询算作数据库启动。修正夹具后通过，没有放宽生产保护。命令、源码摘要和原始结果见[证据](evidence/albums-independent-checkpoint-restore-2026-11-05.json)。

代码尚未部署，恢复结果仍为 `quarantined=true`、`latest_checkpoint_proven=false`、`recovery_ready=false`。指定独立文件及其签名只能确定本次使用的记录，最新异地状态的独立证明、在线切换、历史备份最终擦除及完整注销仍须验证。自动永久清理保持关闭。

来源核对实测覆盖固定文件正确时的完整恢复、预检前新增删除记录及重放后新增删除记录。后两种场景分别在启动前与结束复核时拒绝，既有成功回执保留原样。见[来源核对证据](evidence/albums-restore-source-verification-2026-11-05.json)。
