# 相册接入共享恢复演练

共享 `verify_recovery_bundle` 过去只校验相册备份文件摘要。本次增加隔离 SQL 恢复：两个环境分别校验内部快照与删除检查点，解密、导入、比对每张表的行数和内容摘要，再重放账户、资源和相册删除记录。失败或清理未确认时，整个共享校验不得成功。

不改变快照生成所使用的已登记源码；恢复使用主机上配套安装的校验工具，不执行备份里的 Python 文件。历史快照支持范围沿用现有校验器，不降低签名、表清单或删除检查点的要求。

## 隔离与资源归属

- 恢复只进入新建的 `tellyouwhat-restore-*` 临时 MySQL 容器，禁用网络，不挂载业务数据库；数据目录使用受限 tmpfs，客户端凭据为本次随机生成。
- 相册解密密钥仍来自对应环境独立保管的 `backup.env`，不放进备份包。共享控制面密钥只认证临时工作区的所有权。
- 工作区逐项限定文件名，拥有独立租约。正常、失败和取消均检查容器身份并确认停止后清理；清理失败保留所有权证据，后续由原有工作区清理入口重试。未知文件、外来容器、活跃租约均阻止清理。
- 单个恢复输入不超过 32 MiB，SQL 解压上限沿用 32 GiB；Docker 内存和数据 tmpfs 各限 768 MiB。超出资源范围判定演练失败，不转向在线数据库。

## 安装顺序

使用现有已登记的共享测试发布入口更新配套恢复工具，不能通过任意 SSH/Docker 命令替代。测试发布会验证并一起更新调用方、相册工具和四个 SQL/删除校验模块，失败恢复原文件；先前已审核的两套共享工具字节摘要仍可作为来源，候选目标摘要固定。

生产运维工具安装前检查这些测试发布持有的依赖。依赖未配套时，在复制共享工具前报错；生产发布不会覆盖测试发布独立持有的校验模块。此次仅完成本地实现及验证，没有安装到服务器或修改现有发布选择。

- Docker 创建、身份核对、取消及重试为协议测试。当前机器没有 Docker CLI；未据此宣称真实容器恢复或远端环境验收。

## 验收边界

恢复结果继续标记 `quarantined=true`、`latest_checkpoint_proven=false`、`recovery_ready=false`，不会用于自动上线、签发会话、分享或授权媒体读取。实际服务器上的容器恢复、最新异地删除检查点的独立证明、在线切换、备份永久清理及完整注销闭环仍需各自验证。此次未部署，也未开启自动永久清理。

后续同日已通过[真实 Docker 隔离演练](albums-docker-recovery-verification.md)：两个配置范围各完成正常恢复及三种故障，共 8 个场景。共享服务选择未变，校验工具尚未安装为共享运行版本；其余验收边界保持。
