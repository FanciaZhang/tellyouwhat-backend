# 单机双实例发布与运维

## 运行方式

同一台服务器保留 blue、green 两个版本槽位，每个槽位包含 Gateway、Worker、Admin。原生 Caddy 负责生产入口；MySQL、Redis、对象存储继续共享。新实例先待命，检查通过后接收新请求，旧实例完成已有工作后停止。

| 槽位 | Compose 项目 | Gateway / Worker / Admin 主机端口 |
| --- | --- | --- |
| blue | `tellyouwhat-blue` | 18080 / 18081 / 18082 |
| green | `tellyouwhat-green` | 18180 / 18181 / 18182 |
| 首次接入旧实例 | `tellyouwhat-backend` | 18080 / 18081 / 18082 |

所有应用端口只绑定 loopback。Worker 使用本槽位网络；Journal 开发路由及 18787 上游保持独立。默认蓝绿路径消除已验证发布路径的容器替换空窗；人工中断路径保留资源不足时的发布能力。此拓扑不提供主机故障高可用。

稳定状态只有活动槽位运行，旧槽位停止后不占进程 CPU 或运行内存。应用容器不设置 CPU 核数或百分比配额；争用时由系统调度。Gateway、Worker、Admin 的内存硬上限分别为 384、768、192 MiB，合计 1,344 MiB；该合计不是预留内存、整机内存或吞吐量限制，各服务不能借用其他容器未使用的额度。旧槽停止后上限不会自动提高。达到限制可能发生换页、分配失败或容器 OOM，不能视为有序限流。调整上限必须同步评估活动实例与候选启动预算，不要求平时为停止的槽位预占内存。

## 工作生命周期

生产 Compose 实例启动后默认待命，包括首次升级的 legacy 槽位。发布器或主机巡检在确认活动版本后开放 HTTP 和后台领取。服务控制监听器仅绑定容器内 loopback，使用 `/servicecheck --lifecycle` 调用，无公开业务控制接口，不触发供应商调用。

暂停领取与注册后台工作共享进程锁；确认暂停后不能新增未记录的领取。已注册工作继续执行和结算，不取消上下文。HTTP、SSE、WebSocket、后台批次，以及流式请求结束后的子任务均计入排空；最终封闭接纳和检查空闲在同一锁中完成。控制命令带进程启动 ID，旧进程的命令不能用于重启后的新进程。

单机通过主机操作锁、全实例暂停确认和重启默认待命串行交接后台资格。数据库现有 claim、心跳和幂等结算继续保证任务所有权。本实现不新增跨主机租约或数据库 fencing 协议；扩展到双机时需要另行设计协调机制。

Caddy 生产 Gateway 使用 `stream_close_delay 4h`，配合应用计数保护已有连接；语音会话当前具有最长约 31 分钟的期限。超过四小时仍无法排空时报告异常并保留旧实例，不自动杀进程。应用生命周期变更必须重新验证这一上限。

## 初次启用

这是一项分阶段操作，不能在不具备生命周期能力的旧镜像上直接启用。

1. 通过已验证 PR 发布带 `cn.tellyouwhat.lifecycle=1` 的运行时及主机脚本。此步骤仍使用现有单实例容器替换方式，需要接受现有维护中断。发布器恢复待命服务的接纳；定时器负责重启后的活动服务恢复。
2. 确认内部、公网 HTTPS 及实际业务正常。检查主机资源峰值、Caddy 管理 API、配置导入和备份结果。
3. 在低流量维护窗口执行一次初始化：

   ```sh
   python3 /opt/tellyouwhat/backend/deploy/tencent/release.py bootstrap
   ```

   初始化验证旧实例的生命周期接口和实际代理路由，并给后续代理 reload 建立长连接保护。第一次修改代理配置时，已经存在的旧配置 WebSocket 仍可能重连；不能把这一步当作已经验证的无损切流。
4. 再次发布经过 CI 的目标版本。首次双实例发布启动 green，切流后等待 legacy 排空。下一次使用 blue，此后交替复用两个标准槽位。

不存在 `.operations/blue-green.json` 时，发布器保留单实例方式。不得通过手写该文件跳过初始化校验。合并代码、初始化拓扑、实际双实例发布、长连接业务验收是不同交付阶段。

## 发布门槛

- 当前代理路由与活动记录一致，原版本健康，另一个槽位已空闲。
- 候选内存预算为 1,344 MiB，额外保留 512 MiB；启动前 `MemAvailable` 至少 1,856 MiB。两套服务、独立开发服务与主机余量的总预算不得超过物理内存，Swap 不计入可用容量。
- CPU 在拉取前后分别采样五秒，平均忙碌比例达到 85% 时拒绝蓝绿发布。采样只是发布门槛，不代表性能峰值验收，也不限制平时的 CPU 使用。
- 磁盘拉取前后均不少于 2 GB 且不少于 15%。目标端口无占用，候选端口绑定 loopback。
- 候选所有服务使用检查过的 registry digest；配置明确声明槽位、独立项目和既定内存上限。改变服务内存上限需要重新评估预算。
- 共享数据库位置、数据加密密钥和域名变更被阻止，需要单独协调迁移。所有数据库迁移须经 PR 审查保证新旧版本并行兼容；程序不会自动证明 SQL 的兼容性。
- 继续执行发布前在线备份和定时备份。备份范围仍限于允许保留的管理数据，不能代替全量业务数据恢复。

生产并存峰值和首次实际切流仍需在启用时验收。空闲内存和健康检查不能证明满负载下的延迟、任务恢复或付费用户业务结果。

## 资源不足时的人工中断发布

`Backend CI/CD` 默认尝试蓝绿发布，不会自动退回中断式发布。仅 CPU 或内存容量拒绝会返回退出码 75，在流水线摘要显示是否接受中断的提示和 `Backend Disruptive Deployment` 链接。磁盘不足、端口冲突、测试或镜像失败、配置改变、迁移或就绪失败均不能通过这条入口绕过。

人工入口只提供 `workflow_dispatch`，没有失败事件自动触发器。操作者须单独选择 `main`，填入失败运行 ID、完整 40 位 SHA、原验收阶段，并输入 `interrupt:<完整 SHA>`。输入代表接受本次发布期间的接口不可用、AI 流和语音连接断开，以及未完成任务可能中断；流水线失败或普通发布授权不代表已同意中断。

GitHub 端核验来源是本仓库同一 SHA 的 `Backend CI/CD` 生产运行、测试成功、六个镜像任务成功、实际部署步骤失败。不会重新构建镜像。服务器另行核验私有 `.operations/interruption-offer.json` 中的容量拒绝记录，绑定失败运行、目标版本、原活动槽和配置指纹，最长有效 24 小时。确认文本、版本、环境配置、密钥或活动槽不匹配时拒绝；开始停止服务前消费该记录，不能重复使用。运行记录只有哈希与版本，不输出配置或密钥原文。

确认后的顺序为：核验和拉取镜像 → 校验配置、磁盘和目标端口 → 记录 `INTERRUPTING` 恢复状态 → 暂停旧槽后台领取并停止旧槽 → 检查单实例启动内存余量 → 迁移 → 启动新槽并验证 → 切代理并恢复领取 → `STABLE`。停止最多给予 30 秒宽限，随后可能终止未完成请求，不承诺无中断或固定停机秒数。

失败时先停止候选，再启动旧槽、恢复代理和领取，不依赖两套实例同时运行，不自动恢复数据库。进程中途退出时，定时器拒绝自动推进；`release.py recover` 根据中断策略采用上述单实例恢复顺序。旧版本仍要求与迁移后的数据库兼容。恢复失败时保留日志与状态，禁止盲目删除恢复记录。

此入口只适用于已初始化蓝绿状态且留下容量拒绝记录的主机。首次生命周期基线升级仍按“初次启用”安排独立维护窗口。

## 状态与退出

发布状态依次为 `STABLE → PREPARING → READY → SWITCHING → DRAINING → STABLE`。`.operations/blue-green.json` 保存阶段、活动槽位、候选和前一槽位；`.operations/release.json` 保持可查的当前版本记录。

新版本已经接管但旧版本仍执行任务时，流水线返回 `DRAINING`，不会在 Actions 内等待数小时。主机 `tellyouwhat-deployment.timer` 每约 15 秒执行维护；先确认旧实例停止领取，再恢复活动实例，随后检查排空。至少观察两分钟，并且旧实例连续空闲一分钟后，逐个封闭 HTTP 接纳并停止旧服务。封闭失败或进程 ID 变化会保留实例重试。

旧实例未退出时拒绝下一次发布。发布、回退、恢复和清理共用主机锁；主机控制器无法取得锁时跳过本轮，不干预正在进行的操作。控制器心跳过期会在巡检中显示失败。

每槽的 `.slots/<slot>/<release>/` 保留独立配置与密钥快照；修改候选不会覆盖仍运行的旧槽位。运维工具解析活动槽位，主机备份和定时任务保持单份执行。保留的回退配置和凭据不要手动清理。

## 回退与中断恢复

回退到上一份通过检查的版本：

```sh
python3 /opt/tellyouwhat/backend/deploy/tencent/release.py rollback
```

旧槽位已停止时先检查资源、启动并检查，再切回；因此不保证瞬时回退。回退不会恢复数据库覆盖在线写入，也不会绕过运行时自动保护协议要求。未通过健康检查的候选不能作为回退目标。

中断发布的阶段或代理路由不一致时，停止自动推进并记录恢复要求。核对私有诊断后执行：

```sh
python3 /opt/tellyouwhat/backend/deploy/tencent/release.py recover
```

恢复先暂停候选，再核验原活动实例，恢复原路由和后台资格；候选已经接收的工作继续排空。候选启动失败、完全没有运行服务时也能恢复。恢复再次失败则保留状态和容器，不能通过删除状态文件、强制停止旧实例或自动恢复数据库来绕过。

单独执行一次巡检与排空：

```sh
python3 /opt/tellyouwhat/backend/deploy/tencent/release.py maintain
```

排查时只读取槽位、版本、阶段、聚合计数和无敏感信息的错误分类。环境文件、完整 Docker inspect、备份内容和私有 stderr 不应粘贴进 PR 或公开日志。

## 验证证据

- Go 生命周期测试覆盖待命、暂停与领取竞争、启动 ID、已有请求与后台结算、HTTP/SSE/WebSocket 排空。
- 真实 Caddy 2.11.4 测试覆盖正向和反向 reload、持续短请求、已有 SSE/WebSocket 和慢请求；使用隔离假服务，无生产请求或模型计费。
- Python 状态机测试覆盖正常切换、忙实例保留、下一槽位、快照隔离、迁移/就绪失败、reload 后进程中断恢复、回退及重启恢复；人工中断另测完整版本确认、拒绝记录过期或配置改变、先停后启、迁移失败恢复及切流后进程退出。
- 人工入口测试拒绝 PR、Fork、其他工作流、旧 SHA、跳过或失败的验证/镜像任务及非部署阶段失败。
- CI 运行 MySQL/Redis 业务回归、备份恢复、部署脚本、Compose 校验及镜像构建。隔离测试不能替代生产容量和实际 App 验收。
