# 方舟管理服务

管理后台通过独立 IAM 服务身份访问国内方舟管控 API，固定北京区域、API 版本
`2024-01-01`。推理服务继续使用独立的 Ark API Key。

## 身份与权限

服务使用官方 Go SDK 签名，从 `ARK_MANAGEMENT_CREDENTIAL_FILE` 指定的 JSON
文件读取 `accessKey`、`secretKey`。文件权限为 0400 或 0600，大小不超过 8 KiB。
不读取个人 CLI 配置或环境 AK/SK。CLI 用于人工授权、运维核验及专用测试资源；
后台运行不依赖 CLI 登录，也不依赖个人登录续期。服务密钥需要按运维制度轮换，
撤销或禁用后请求会失败；不能将长期密钥理解为永久有效。

只读策略见 [ark-admin-read.json](../../config/iam/ark-admin-read.json)，原生写策略
见 [ark-admin-rolling.json](../../config/iam/ark-admin-rolling.json)。三个写动作采用
账号范围 Resource `*`。Health 范围由后台的环境绑定白名单限制，排除与手记共享
的接入点；HTTP 入口、预览、指令提交和后台执行器分别检查归属。服务凭证本身
可以访问比 Health 更大的范围，必须仅挂载给 admin 容器。

追加 `compose.ark-management.yaml`，设置 `ARK_MANAGEMENT_CREDENTIAL_HOST_FILE`
为主机私有文件的绝对路径。文件缺失时不自动创建；容器内文件所有者需与管理
进程 UID 65532 一致。密钥不进入仓库、共享环境文件或业务容器。

## 生产发布

GitHub `production` 环境的 `ARK_MANAGEMENT_CREDENTIALS_JSON` 保存服务身份 JSON，
`PRODUCTION_ENV_FILE` 中分别设置 `AI_CONFIG_WRITES_ENABLED=true` 和
`AI_ENDPOINT_WRITES_ENABLED=true`。两个开关默认关闭；凭证存在时仍可保持只读。
密钥值不得放入共享环境文件。正常发布由主分支 CI 完成备份、迁移和就绪检查。

发布流水线验证 JSON 后，将凭证安装到服务器 `.ark-management/` 下独立的随机
版本文件，权限 0600、所有者 UID 65532。环境文件只保存该路径。发布、迁移前
检查和日常运行统一选择 `compose.ark-management.yaml`，仅 admin 能读取挂载。
缺失文件、错误所有者、公开权限或不完整挂载会在运行迁移前失败。

发布快照保存 Compose 与凭证路径，不将密钥复制到 Apple 密钥共享目录。
回滚恢复旧版本路径和开关；旧版本没有管理凭证时不加载挂载。版本文件保留至
对应发布不再需要回滚后，由运维清理；轮换并撤销旧 AK 后，旧发布的云端操作
也会失效，应先更新回滚版本的授权方案。

## 功能配置

管理后台可为八个 Health 功能指定接入点、思考深度、联网开关。联网仅适用于
`meal_decision`，其他功能保持数据边界。超时由服务端配置。历史配置通过新建
草稿恢复；发布需要检查基线、Passkey 再次验证、CSRF、防重复提交标识和五分钟
有效的服务端签名预览。配置、幂等结果、审计在一个 MySQL 事务中提交。

新同步、流式及入队请求读取发布版本，排队任务保留加密的配置快照。Worker
不重新读取当前功能配置；实际模型仍由接入点在请求发出时决定。覆盖选项后会
再次检查该请求版本的 Prompt Manifest。BYOK 和手记请求不进入此配置路径。

## 模型目录与兼容性

目录、版本、账号开通状态、价格及允许升级的目标分别验证。选中模型后单独
读取其开通状态与账号价格，不依赖全账号价格目录同步成功。管理目录缓存 30 秒，
失败保留最近成功数据及原同步时间并标记过期；发布和灰度预览读取实时信息。
账号价格分页采用 20 项，模型切换使用按模型过滤的价格查询。管理客户端共享
每秒最多两次请求的节奏；只读查询遇到限流时最多重试两次，受原请求截止时间
约束。原生写操作不自动重发。

目录保留火山返回的所有模型，支持搜索和版本选择。生成图片、视频或向量等模型
可查看，但不能替代需要结构化理解结果的功能。账号开通、价格、功能协议与
当前接入点的原生升级条件分别检查；缺失的能力信息不会当作已支持。

兼容性证据版本为 `health-responses-scoped-2026-09-08`。既有 mini/lite 证据可复用，
目录新版本可直接触发运行时检查，不需要修改模型允许列表。检查通过生产请求
序列化、普通及流式解析、JSON Schema 校验路径，使用固定合成文本、32 像素图片
或一秒静音，按实际功能验证思考和搜索参数，不读取健康数据。检查使用服务端
`HEALTH_ARK_API_KEY`，推理地址固定为国内北京方舟。单次输出限制 2048 tokens、
每组检查最多 55 秒，同时最多两组；成功证据缓存六小时，失败一分钟后可重试。
检查产生少量模型调用费用，不改变接入点。等待结果返回 HTTP 202，页面自动查询。

接入点要求根据当前发布绑定和仍可能被排队任务持有的历史配置计算，不要求每个
模型支持全部八项功能。未接管功能仍检查 App 可提交的参数范围；可以先发布所需
参数再切换模型。切换指令持久化前重新检查要求，发往火山前再次核对；新增要求会
阻止旧指令执行。有排队任务时保守保留历史绑定和参数要求，队列排空后仅检查当前绑定。参数发布与该接入点指令提交共享数据库锁，并检查待执行目标。
最后的火山 DryRun 才决定此接入点是否能升级到所选版本。

## 管理页面

AI 管理分为功能配置、模型与接入点、变更记录。概览每行直接提供参数与切换模型
入口。参数编辑先保存未发布草稿并显示差异，最终发布只需一次 Passkey。接入点
按 ID 去重，显示实际模型及受影响功能；模型选择使用完整目录，不依赖全账号价格
同步。检查页显示所选版本开通状态与分档单价，确认页显示新旧费用预留上限。

进度页每五秒读取云端状态，隐藏页面时暂停轮询。新模型达到 100% 且接入点真实
绑定已改变才显示完成；这时“切回原模型”重新检查并创建新的原生灰度，不能撤销
已经完成的任务。灰度期间保留原生回退和撤销操作，流量比例以火山返回为准。

## 原生灰度

后台提供切换预览、开始灰度、回退一个阶段、撤销灰度及操作记录。预览绑定
管理员、接入点、源/目标模型、原生任务状态、费用上界和兼容性配置版本；状态
变化要求重新预览。指令写入数据库后返回 202，由 admin 后台执行器处理。

使用 [国内 API Explorer](https://api.volcengine.com/api-explorer/?action=CreateEndpointRolling&serviceCode=ark&version=2024-01-01)
定义的 Create/Get/Rollback/CancelEndpointRolling。DryRunOperation 表示预检通过。
火山自动推进灰度；后台不自行按百分比分流，不提供未经公开 API 支持的任意
比例或手动全量接口。回退仅退一个阶段；撤销使新模型流量归零并终止任务。

每个接入点的数据库锁串行化提交和执行，状态先从 queued 持久化为 dispatching
再调用火山。SDK 不自动重试写请求。超时或重启后的不确定结果进入 uncertain，
不重复创建或回退；已知原生 ID 的任务持续查询状态。创建响应丢失时，由管理员
在预览中核对源/目标及原生 ID，使用“核对并关联云端任务”恢复跟踪。此操作只
关联本地记录，不再次调用写 API。没有可核对的匹配云端任务时保留待核对状态。

管理员关闭写开关后，已提交的云端灰度仍由火山推进，后台继续读取和核对；
尚未发出的本地指令暂停。无法识别的终态保持等待，不猜测成功。观察到 100%
且接入点已绑定目标模型才记录完成，Reverted/0% 记录撤销。

## 费用与请求记录

提交模型切换时，在同一事务持久化新旧模型最高单价。价格覆盖音频输入和全部
上下文档位，取账号价及原价较高者，以整数纳元计算；缺少必要价格或单位未知
时拒绝切换。Token 费用账本为保守上界，不是火山账单的精确复现，也不包含工具单独收费。

每次请求，包括旧排队任务，都读取接入点当前费用上界。费用预留和灰度提交
共享接入点锁；灰度提交前等待早于指令的在途预留结束，新请求使用新上界。
每次调用保存自己的单价，完成时不会因另一管理员切换配置而使用不同单价。
模型价格上界保守保留历史最大值，避免旧任务或灰度回退出现低估。

admin 定期刷新接入点及价格；已接管接入点的同步超过五分钟、价格缺失或发现
未认可的模型变化时，网关和 Worker 拒绝新的费用预留。首次接管前保留原环境
价格。网关和 Worker 只读数据库，不需要管控 AK/SK。

最近实际模型仅取推理响应 `model`，缺失时显示未知，不从接入点推断。记录仅含
功能、接入点、配置版本、实际模型、单价和时间，无提示词、媒体、用户标识。
实际模型未知或无法核实时保留整个费用预留；异常模型阻止后续请求。
管理员可实时核对并确认当前兼容模型与价格，解除已处理异常的阻断；这不会
修改云端模型或流量。运行记录
保留 30 天，指令及审计按控制面备份管理。

## 部署与验证

先执行 `0005_health_ai_config.sql`、`0006_health_ai_rollout.sql`，再更新 admin、
gateway、worker 到同一版本。配置、指令、价格及运行记录纳入加密备份。
确认项目费用控制配置有效、所有 Health 推理进程已更新后，按需打开
`AI_CONFIG_WRITES_ENABLED` 和 `AI_ENDPOINT_WRITES_ENABLED`，两个开关默认 false，
独立于 Offer 写入开关。开启原生操作需配置功能写开关及服务凭证。

本地 MySQL 测试要求 `MYSQL_TEST_DSN` 指向独立的 `_test` 数据库；无环境变量时
跳过不能算作存储验收。原生云端测试要求显式服务凭证和名为
`health-ai-admin-validation-*` 的专用接入点。详细证据见[验收记录](ark-management-validation.md)。
生产部署、生产 Passkey 全流程及原生自动推进到 100% 的云端验收分别记录，不能
以合成页面测试或局部原生操作替代。
