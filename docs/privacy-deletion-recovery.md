# 隐私删除结果恢复

`DELETE /v1/privacy/data` 的首次执行仍要求完整 App Attest 认证。后端对应用、方法、路径、请求 ID、Key ID、断言、Nonce、时间和请求正文摘要生成带长度边界的 SHA-256 完成摘要。

对象与缓存清理成功后，MySQL 在删除身份及关联数据的同一个事务中写入 `privacy_deletion_receipts`。摘要写入失败会回滚身份及其级联删除；不能在删除事务提交后单独补写结果。只有已提交的完成摘要可以使相同删除请求再次返回 204，其他路径和普通 API 仍使用原认证规则。

表中只保存 App ID、32 字节完成摘要及完成时间，不保存原始设备身份、断言、订阅交易、照片或健康正文。摘要保留用于离线或重启后的删除结果确认，不随原 Nonce 到期失效；当前没有自动过期清理。该保留目的与范围应在客户端隐私说明中披露，不能将摘要称为不存在或保证匿名。

客户端必须在发送前持久化完整原证明，并在结果确认前阻止普通请求重新注册身份。网络错误、取消、5xx 和结果不确定都保留证明；只能在确认 204 后清理。若某次失败已消费 Nonce，客户端可以用同一原 Key 生成新证明，但必须保留此前所有未确认请求，防止并发提交或断线时丢失唯一可验证的成功结果。不能把 401 或 409 直接当作删除成功。

迁移 `0003_privacy_deletion_receipts.sql` 与旧字段兼容，应先执行迁移再切换网关。旧客户端仍可完成正常删除；响应丢失的恢复需要对应客户端改动。部署回旧网关会暂时失去结果重放能力，不能因此清理客户端恢复记录。

本协议只确认该请求已经完成的删除事务，不解决其他设备发起的关联删除、已过期且无法恢复的注册证明、备份恢复、在途任务或后续重新创建的数据。这些路径需要单独的生命周期和存储验收。
